# AI Interaction Map

A structured knowledge system mapping what AI can do, built for UX designers, product builders, and curious learners. Version 1.0.

## What it is

16 AI capability layers, organized into six categories, each covering a different kind of thing AI does.

## Category Key

| Category | Focus |
|---|---|
| Perception | AI reads and interprets input |
| Generation | AI creates new content |
| Communication | AI exchanges meaning |
| Reasoning | AI thinks and decides |
| Memory | AI stores and retrieves knowledge |
| Action | AI acts in the world |

## Learning Paths

**Beginner Path** (6 stops, no technical background needed): Classify → Summarize → Generate → Converse → Retrieve → Recommend

**Builder Path** (10 stops, with tool recommendations and hands-on experiments): Classify → Retrieve → Generate → Converse → Summarize → Extract → Transform → Rank → Reason → Plan + Execute

## Supporting Frameworks

### Trust & Transparency: A Cross-Cutting Framework
The interface design decisions that look like UX details are actually governance decisions. Maps where control, trust, and responsibility break down across all 16 layers, and what design choices close or widen that gap. Includes nine design principles and a full layer risk matrix. This framework connects directly to the book's thesis: the interface is not the system, and trust breaks at the layer boundaries that design usually treats as cosmetic.

### Layer Relationships & Connection Map
No AI layer works in isolation. Maps five core dependency chains: the Agentic Loop, the Data Pipeline, Content Production, Search & Discovery, and Modality Flow. Includes a layer-by-layer connection matrix, the five central hub layers, and minimal viable stacks for seven product types.

### Product Teardowns: Real AI Stacks
Breaks down how real products combine layers into working systems. Teardowns of Spotify, Gmail, GitHub Copilot, Notion AI, Tesla Autopilot, and Intercom Fin, each showing the exact layer stack and what each layer is doing in that product.

### Glossary
Definitions of the core terminology used across the Atlas: AI capabilities, architectural concepts, and design vocabulary.

## Why This Matters for Content and Consulting Work

This map is a naming tool. When content references "AI," it should name the actual layer (Retrieve, Reason, Classify) or the actual category (Perception, Memory, Action) instead of talking about "AI" as one undifferentiated thing. That precision is a large part of what separates this content from generic AI commentary: most writing about AI treats it as a single technology, when it's really a stack of distinct capabilities that fail in different ways and for different reasons.

The Trust & Transparency framework is the strongest bridge to the book. Both make the same argument from different angles: the visible layer (interface, or capability) is not the whole story. Control and responsibility live underneath it.
